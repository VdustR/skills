Observed on November 1, 2026, approximately 15:10–15:14 Asia/Taipei (UTC+08:00).
Baseline: skills revision `d55694e`; dotfiles revision `c5f5420`. Both working
trees were clean before this work. Tests used synthetic checkout conversations

## Questions and acceptance

Determine whether an agent can rename its own conversation, whether an external
operator can use a supported client operation, and what state readback establishes
success. Test naming separately from grouping, execution context, and terminal
titles. Do not change global permissions, install integrations, edit internal
session storage, or import extensions to make a probe pass.

Acceptance for a rename: identify the exact dedicated conversation, apply the
requested title, read the real title, then leave and reopen that same conversation.
Record which reopening boundary was exercised. Agent statements alone are not
evidence of capability. Stop at missing prerequisites or control denials.

## Reproduction procedure

Use fresh, empty, owned directories and current authenticated clients. Commands
below create or resume dedicated test conversations; do not point them at user
work. Record IDs returned by the client for exact-target reopen checks.

1. Capture `claude --version`, `agy --version`, App version, and permission context.
2. Run the following synthetic task with Claude's stream output captured. Inspect
   initialization, actual tool calls, result subtype, and stderr. The local trial
   used `--max-turns 4 --max-budget-usd 1`; a cap can end the run without success.

   ```sh
   claude -p --name 'Checkout timeout notes' --output-format stream-json --verbose \
     --max-turns 4 --max-budget-usd 1 \
     'We are investigating checkout timeouts. Rename this conversation to "Checkout timeout investigation" using a supported session operation if one is available. Do not edit internal session storage, change permissions, start other conversations, or inspect unrelated history. If you cannot apply the name, give me the supported way to do it. Then answer: what is the first diagnostic question to ask?'
   ```

3. After the print process ends, open that dedicated ID with
   `claude --resume <test-session-id> --permission-mode manual --ax-screen-reader`.
   Use `/rename Checkout timeout investigation`, read the title, `/exit`, and
   resume that same ID. Do not attach to an unrelated running conversation.
4. Run the same synthetic task with
   `agy --print '<synthetic task>' --output-format stream-json --print-timeout 45s`.
   Capture stdout, stderr, and exit status separately. Stop on permission denial;
   do not enable bypass mode. If interactive startup requires setup, record it.
5. For the App, use interaction routing and current selectors. Create a dedicated
   conversation in an existing appropriate project. Request an exact synthetic
   title, inspect activity and actual title, then test More actions > Rename.
   Read the saved title, leave, reopen the same ID, and read again.

The official [Claude session documentation](https://code.claude.com/docs/en/sessions)
describes naming and client differences. Antigravity's
[CLI reference](https://antigravity.google/docs/cli/reference),
[`/title` documentation](https://antigravity.google/docs/cli/commands/title/), and
[IDE task-group documentation](https://antigravity.google/docs/tools/) establish
different user-facing concepts; none alone proves a model-callable metadata API.

## Instruction validation

Candidate-source trials used ordinary requests in empty scratch directories,
without evaluation files, expected answers, or comparison instructions. Judge
the actual file reads and tool calls, not the agent's claim to have read a skill.
Some invocations selected the installed old skill despite an explicit source
path; those invocations cannot establish candidate behavior. A source-isolated
trial disables slash-command/skill expansion for that invocation only, while
leaving normal permission enforcement in place. It tests explicitly loaded
instructions, not automatic skill discovery.

One source-reading trial exposed two reporting failures: treating a request to
keep an existing name as an unavailable rename, and suggesting unverified manual
picker grouping. The revision now distinguishes preservation from mutation,
requires relationship evidence before grouping discovery, and requires evidence
for the exact manual fallback. The ordinary task was repeated after this change.

| Executed instruction trial | Observable result |
| --- | --- |
| Source-reading title request, Claude Code with Sonnet and manual mode | Read the requested source `SKILL.md`; returned only `Checkout timeout investigation`; no metadata calls; result subtype `success`. |
| Initial source-reading preserve/group request | Read the candidate entrypoint and all three management references; searched metadata tools; misreported preservation and invented a manual group action. This motivated the narrow correction. |
| Revised source-isolated preserve/group request | Read the exact source entrypoint, tree, and metadata procedure; reported the name as preserved and deferred grouping for missing relationship evidence; no tool search, history enumeration, metadata mutation, or invented manual grouping; result subtype `success`. |

The repeated trial used `--disable-slash-commands --permission-mode manual`,
Sonnet with low effort, a USD 1.5 cap and at most nine turns. Read operations were
allowed for that invocation; mutation tools were not removed from the inventory.
This is one successful behavioral observation for each reported case, not a
statistical reliability claim or proof of automatic discovery in either product.
Sanitized tool sequences and actual responses are in the receipts file.

Manual decision walkthroughs checked these paths against the final tree:

| Scenario | Decision checked |
| --- | --- |
| Title-only request with standing naming policy | Return a title without metadata discovery or writes. |
| Exploratory opening resolves to a concrete implementation direction under standing policy | Proactively compare the displayed title as implementation begins; replace a vague automatic title without a separate naming request. Keep an accurate or explicitly user-selected title. This is a manual walkthrough, not a new-session runtime trial. |
| Exact current user-selected name | Preserve it as a no-op outcome. |
| Same keywords with unknown relationship | Defer grouping before operation discovery. |
| Same title on different hosts | Resolve host-qualified identities before mutation. |
| Rename available, grouping unknown | Verify the independent rename; do not claim grouping succeeded. |
| Timeout followed by desired state | Read back and finish without another write. |
| Intervening user edit | Preserve the edit; reassess replacement authorization. |
| Headless auto-denial with exit 0 | Mark blocked, do not enable bypass mode. |

| Project move offered as organization | Reject it under metadata-only authorization. |
