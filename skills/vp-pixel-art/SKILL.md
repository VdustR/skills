# Pixel artwork

Produce deliberate native-grid artwork with editable source and exact-size exports for the declared use. Reconstructing a reference is one mode; direct pixel construction from a brief is supported.

## Choose the work

Use [modes and capabilities](references/modes-and-capabilities.md) to select create, reconstruct, adapt, edit or review and establish available capabilities. Image generation is optional. Honor an explicit image-first requirement; if generation is unavailable, disclose the gap and obtain a route decision before substituting direct construction. A supplied reference or an agreed brief-only route can work without image generation. Missing image observation leaves visual acceptance unverified.

Read [review gates](references/review-gates.md) for the task's acceptance contract and evidence boundaries. Brief-only creation derives criteria from the brief and declared design choices, without invented image observations.

Inspect an existing asset/source before modifying it. Record essential identity, detail roles, style, permitted adaptations, actual sizes/backgrounds and required consuming actions. Scale this contract to the task. Review mode is read-only unless fixes are requested. Preserve approved unusual styles and accepted versions.

## Establish the target

Declare native dimensions, aspect/pixel aspect, palette/alpha limits, minimum readable size, style and any animation/tile/export constraints. Distinguish a platform-inspired style from compatibility with real platform constraints. If claiming real hardware compatibility, verify the requested platform's relevant palette, tile, sprite, memory and display constraints against primary technical documentation; a palette count alone is insufficient.

For a reference, allocate identity-bearing features to actual pixels before polishing. Record what will be simplified, rearranged or omitted and why; preserve required object/function/action readings. Do not reduce a high-resolution source and call it deliberate pixel construction without inspecting and authoring the native result.

## Construct and inspect

Use an available pixel editor or reproducible native-grid construction. Retain editable layers or source data/code and palette as appropriate. Export the exact native dimensions; use nearest-neighbor enlargement for inspection, with no accidental smoothing or fractional resizing. Validate dimensions, allowed colors, transparency and source/export rebuild consistency where required. Apply the same grid, palette and alpha limits to every exported or edited variant. A local recolor can add a color beyond the limit, while changing a shared palette entry can alter unrelated roles; verify both the resulting palette and the unchanged region before accepting the edit.

Inspect native size as well as enlargement: silhouette, value grouping, clusters, line rhythm, identity, critical gaps and adjacent-object separation. Diagnostic silhouette/value/cluster views are conditional tools for a concrete uncertainty, not mandatory ceremony. Do not delete tiny clusters by a universal threshold: an isolated pixel may be an eye, needle or required highlight. Avoid imposing one outlining, dithering or shading style on every approved style.

Treat a new size/palette/platform as an adaptation, not an automatic resample. Reallocate pixels and rerun relevant readability checks. For animation or tiles when requested, inspect timing, continuity, seams and actual engine import behavior. Emulator/static-frame evidence is not physical-device evidence; record exactly what ran.

## Deliver and decide

Deliver editable source, native exports and only the requested previews/engine assets, with a scoped review result and evidence gaps. Apply integrated gates; fix evidenced required failures and rerun affected checks. Preserve accepted versions and reject/revert required regressions.
