# Repository Conventions

Inspect local instructions, architecture boundaries, supported runtimes, module
style, test organization, generated-code policy, and dependency ownership.

Prefer existing adapters, validation libraries, codemods, and test helpers.
Match neighboring code only when it is still an accepted pattern; deprecated
local examples are evidence of current usage, not necessarily the target design.

Update public setup or behavior documentation when the migration changes it.
Keep unrelated cleanup out of scope.
