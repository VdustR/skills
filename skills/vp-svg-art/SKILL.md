# SVG artwork

Produce intentional editable vector geometry and appropriate exports for the declared use. Tracing is one reconstruction route; direct drawing from a brief is supported.

## Choose the work

Use [modes and capabilities](references/modes-and-capabilities.md) to select create, reconstruct, adapt, edit or review and establish available capabilities. Image generation is optional. Honor an explicit image-first requirement; if generation is unavailable, disclose the gap and obtain a route decision before substituting direct construction. A supplied reference or an agreed brief-only route can work without image generation. Missing image observation leaves visual acceptance unverified.

Read [review gates](references/review-gates.md) for the task's acceptance contract and evidence boundaries. Brief-only creation derives criteria from the brief and declared design choices, without invented image observations.

Inspect an existing asset/source before modifying it. Record essential identity, detail roles, style, permitted adaptations, actual sizes/backgrounds and required consuming actions. Scale this contract to the task. Review mode is read-only unless fixes are requested. Preserve approved unusual styles and accepted versions.

## Construct the asset

Choose direct geometry, manual tracing, automatic tracing with inspected cleanup, semantic rebuilding, or a scoped source edit based on the required fidelity and editability. Do not invent a requirement to trace every raster pixel. A raster embedded in an SVG wrapper does not fulfill a genuine vector request; disclose any intentional raster component and agree on the changed contract.

Keep a readable master with semantic groups, deliberate geometry, viewBox, palette and separable parts for requested edits. Separate optimized exports from the editable master. For repeated inline embedding, namespace IDs and references per instance, and scope selectors so editing one instance cannot alter another. A filename prefix alone does not distinguish repeated copies.

Use destination composition only when that destination is in scope:
- Logos: silhouette, counters, negative space, mono/polarity variants and native minimum-size readability. Produce a dedicated optical small-size variant when necessary, preserving larger accepted geometry.
- Website illustrations: actual copy, reserved copy area, crop/aspect behavior and required wide/narrow contexts. Do not include page layout implementation unless requested.
- Slide graphics: brief-defined order and relationships, projection-size hierarchy and space for live labels. Where editability is requested, keep labels as native text in the destination; converting text to paths is not text editing. Use an available destination-native presentation workflow to author the deck and native text; this skill owns artwork, not the whole presentation. Do not silently choose SVG when a slide request needs only native shapes/text.

For reference-led illustration, assess the requested style on focal subjects as well as backgrounds. Gradients or transparency in one region do not establish whole-image style fidelity; inspect actual contours, ink, value and material relationships against the source. Render at actual use sizes and inspect required details and whole composition. Perform a concrete requested component/color/text edit and verify unrelated parts remain intact when editability is a requirement. Test actual target-app import/edit/export actions when required and available; another renderer does not prove that consumer. Validate XML/vector structure, geometry bounds and ID/reference integrity as relevant. A generic renderer pass does not prove visual quality.

## Deliver and decide

Deliver the master, required exports and scoped review result with evidence and remaining gaps. Apply the integrated gates; correct demonstrated failures and rerun affected checks. Preserve or revert regressions instead of trading a required detail for a higher average score.
