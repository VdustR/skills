# Modes and capability negotiation

Choose the requested deliverable before the production route. SVG means real editable vector artwork. Pixel art means an intentional native grid, not merely a pixel-style appearance. PNG/SVG extension, harness brand and a tool's advertised name do not establish these properties.

## Modes

| Mode | Input and expected behavior | Mutation boundary |
| --- | --- | --- |
| create | Start from a text brief/project standard. Record required identity, story, sizes, color/background roles, style authority and edit/use tasks. Direct native construction is valid; image generation is optional when useful and available. | New candidate/master only |
| reconstruct | Use a supplied/generated reference. Observe actual source pixels before candidates; freeze required/simplifiable/optional roles and allowed adaptations. SVG may trace, rebuild or locally edit; pixel art reallocates features deliberately at the native grid. | Preserve source; create a separate master |
| adapt | Change size, palette, background, aspect or platform. Record permitted representational changes before constructing. Inspect each optical/platform variant independently. | Preserve accepted versions |
| edit | Change the requested component or region. Read current source and callers/context; keep all unrequested behavior intact. Test the edit on a copy where needed. | Only authorized change; no unrelated redesign |
| review | Inspect existing artifacts against the brief/reference/use, report located required failures and evidence limits. A review can recommend corrections without executing them. | Read-only unless fixes were requested |

Trace is a reconstruct route, not the scope of either skill. Do not regenerate a supplied reference merely because generation is available. Do not invent source observations for create mode: roles come from the written brief, project standard or explicitly delegated direction. A direct-from-brief task can complete without a reference image, while source-fidelity criteria are not applicable. Rendered-deliverable visual review still applies.

## Capability matrix

Check the exposed capability for this run, not assumptions about a harness:

| Capability | Supported behavior | Missing capability consequence |
| --- | --- | --- |
| image generation | Optional concept/reference exploration through the host's available approved workflow | Continue with supplied references or agreed direct construction. If reference generation was explicitly required, defer that stage and state the missing capability; do not silently change the brief |
| image observation | Inspect actual references and rendered native/minimum/context outputs | Technical construction/checks can continue; visual gates remain not_verified. Do not certify visual quality from code or counts |
| source authoring | Construct/edit SVG geometry or explicit native-grid source | Report the specific missing production path; do not wrap a raster and call it pure vector |
| rendering/export | Obtain actual intended-size and relevant-context previews | Source validity may be checked, but unrendered visual/use acceptance stays not_verified |
| target application/runtime | Exercise a required browser, slide editor, engine, ROM or device action | Keep that target gate not_verified; another renderer does not prove it |
| independent review | Separate actual reviewer execution when authorized | Label self-review accurately. If independence is required, missing independent evidence remains not_verified |

No installation, external write, delegation or alternate API is authorized merely by loading this skill. Use the host's applicable workflows and existing authorization. Never invent a generation API or imply that a missing tool was used.

A text-only request is not permission to generate a raster reference when the user prohibited it. Conversely, an explicit image-first request cannot be fulfilled by quietly substituting direct code drawing. If a tool gap changes the requested result materially, finish independent preparation and ask only about the necessary choice.

## Ambiguous destinations and small edits

For “make a website illustration” or “make a logo” without an output format, use existing project conventions, supplied references and requested editability/target constraints to choose a route. Do not force SVG onto photography/painterly raster work. Ask a narrow format question when the choice materially changes the result and context does not settle it.

An ordinary stroke/color/position change to an existing code-native UI icon does not need the full art workflow. Use a lightweight edit path or existing icon/design-system workflow. If the request instead changes artwork identity, creates a custom mark, adapts an optical size or asks for art review, select the relevant art mode.
